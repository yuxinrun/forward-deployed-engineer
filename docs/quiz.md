# FDE 适配度自评：你能不能扛住现场

先说清楚这不是什么：<strong>这不是招聘筛选，不预测你能不能拿到 offer，也不计分成绩单。</strong>十道题测的是"偏好"，不是"能力"——能力可以练，偏好硬拧通常会在第三个月出问题。

为什么值得花三十秒测一下：这一行最常见的失败不是技术不过关，而是**入职之后才发现自己受不了那种活法**。国内一条 JD 原话写的是"长期驻场在客户现场（时间占比可能高达 50% 或以上）"`[A]`；美国同岗位有公司写 up to 25%，也有公司写 30–50%。这两个数字描述的是完全不同的人生安排，但它们都叫 FDE。

| 维度 | 它在现场长什么样 | 为什么这一项最难练 |
| --- | --- | --- |
| 模糊耐受 | 客户说"我们想要个 AI，你看着办"，你得先把这句话逼成一个能验收的动作 | 工程师的训练是"把需求写清楚再开工"，而这行的日常是没有清楚的需求 |
| 工程手感 | 只剩两天，你砍范围还是通宵硬堆 | 这一项低分通常说明还没被生产环境教育过，跟聪明程度无关 |
| 与人打交道 | 业务方当着领导说"不好用"，你追问还是解释 | 解释是技术人的本能，追问是反本能的 |
| 现场容忍 | 内网、没有外网、装依赖审批三周 | 这一项没法靠练习提高，只能靠提前知道自己受不受得了 |
| 学习速度 | 一周内用陌生工具链跑通最小闭环 | 现场不会等你上完一门课 |
| 责任心 | 半夜告警，是不是你起来看 | "交付"这两个字的真正含义是：出事的时候你在 |
| 商业意识 | 客户问"加这个多少钱、什么时候验收"，你答不答得上 | 大部分工程师从来没被要求同时给出范围、人力和风险 |
| 写作 | 你的文档能不能被对方 IT 和法务照着评审通过 | 让误解必然报错，是这一行最被低估的技能 |
| 生活安排 | 一年 60–100 天不在自己城市 | 这是真约束，不是心态问题。硬撑的结果通常是干一年就想回去 |
| 自我定位 | 成功时你最想让谁知道 | 选"客户 + 我的产品团队"的人，天然在做双向传输那件事 |

## 三件比分数更重要的事

**一、分数低不代表进不去，代表进去会难受。** 招聘方看的是能不能干活，自己得清楚的是愿不愿意那样干活。这两个判断经常不一致，而后者决定了你能干多久。

**二、"现场容忍"和"生活安排"这两项，不要用意志力补。** 出差和驻场是物理约束。国内有从业者算过一笔反差账：拿到 5 万月薪的第一天，任务是进厂贴二维码、敲台账`[C]`——钱是真的，环境也是真的。

**三、真正拉开差距的那一栏是"写作"。** 一个岗位的 JD 里如果写着"将客户现场的定制化实践经验抽象提炼，转化为通用产品能力或解决方案组件"`[B]`，说明这家公司真的在做产品反哺；如果写着"完成领导交办的其他工作"，那它买的其实是一个驻场人力。
