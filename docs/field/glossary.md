# 现场术语表：53 个绕不开的词

这份表不是"技术名词大全"，是**你在会议室里会真的听到、听不懂就要命的词**。

判断一个词该不该进表，本站用的标准只有一条：<strong>它是否会在某次会议上被用来做一个决定。</strong>所以"Transformer 架构"不在表里（它很少直接决定你能不能验收），而"质保金"在表里（它决定你尾款什么时候到账）。

## 一、交付与项目节奏（12 个）

| 中文 | 英文 | 一句话解释 | 现场为什么绕不开 |
| --- | --- | --- | --- |
| 概念验证 | POC (Proof of Concept) | 用最小成本回答"这条路走不走得通" | 最常见的死法：POC 成功之后没人定义谁拍板 |
| 试点 | Pilot | 在有限范围里用真数据真用户跑一段时间 | 试点的目标是"能否复制"，不是"能否跑通" |
| 试点瘫痪 | Pilot Paralysis | 试点一直成功、一直不扩张 | McKinsey 用它描述大多数企业 AI 项目的真实状态 `[C]` |
| ★ 首次价值时间 | TTFV (Time to First Value) | 从注册/进场到第一次真的产生价值的时间 | 客户续约看的是它，不是你写了多少接口 |
| 生产化 | Productionization | 把能跑的东西变成能被运维、被审计、被叫醒的系统 | 这段距离通常比开发本身长 4–12 周 |
| ★ 变更单 | Change Order / CR | 范围改动的书面记录：谁提、影响什么、谁确认 | "顺手加个小功能"唯一的解药 |
| 上线 | Go-live / Cutover | 真实用户开始承担后果的那一天 | 上线不是终点，是口碑开始漏气的起点 |
| 值守 | On-call | 出事时轮到你被叫醒 | 判断一个岗位真不真的"端到端负责"，问这一条最快 |
| 升级路径 | Escalation Path | 你解决不了时依次找谁 | 没有它的团队，会把每一次故障变成一次吵架 |
| ★ 运行手册 | Runbook | 照着做就能处理的步骤清单 | 它是"交接"能不能真的发生的关键交付物 |
| 验收 | Acceptance / UAT | 把交付物对齐到合同上那几行字 | 卡在这里的项目，通常卡在条款是形容词 |
| 扩展 | Expansion / Scale-out | 从第二个部门、第二个场景开始复制 | 决定这家公司毛利，也决定你会不会变成长期外包 |

## 二、数据与集成（10 个）

| 中文 | 英文 | 一句话解释 | 现场为什么绕不开 |
| --- | --- | --- | --- |
| ★ 字段语义 | Field Semantics | 这一列在业务里到底是什么意思 | 同名不同义是数据事故的第一根因 |
| 数据血缘 | Data Lineage | 这个数从哪张表经过哪些加工来到这里 | 审计问的第一句就是这个 |
| 出处与可追溯 | Provenance | 一条回答能不能指回原始材料 | 没有它，你的系统只能说"我觉得" |
| 模式漂移 | Schema Drift | 上游改了字段而没人告诉你 | 集成项目最常见的静默失败 |
| 抽取转换加载 | ETL / ELT | 把数据搬过来并整理成能用的形状 | FDE 工作量里最不上镜但最真实的一块 |
| 数据不出域 | Data Residency | 数据不许离开某个物理或逻辑边界 | 在国内它常常直接决定架构 |
| 内网隔离 | Air-gapped | 环境没有外网连接 | 意味着离线包、镜像、依赖清单都是交付物 |
| ★ 脏数据三件套 | Nulls / Duplicates / Encoding | 空值、重复、编码错乱 | 任何一次现场演练都躲不过 |
| 单点登录 | SSO (SAML/OIDC) | 用客户已有账号体系登录 | 接不进去，业务方就不可能真用 |
| 权限模型 | RBAC / ABAC | 谁能看什么、做什么 | 演示环境里没有它，生产里全是它 |

## 三、现代 AI 栈（12 个）

| 中文 | 英文 | 一句话解释 | 现场为什么绕不开 |
| --- | --- | --- | --- |
| 检索增强生成 | RAG | 先查资料，再让模型根据资料回答 | 甲方最常见的第一个需求，也是最容易做浅的一个 |
| 嵌入 | Embedding | 把文本变成向量，用来算相似度 | 模型选型可以换，嵌入索引重算很贵 |
| 切块 | Chunking | 把长文档切成检索的最小单位 | 远程看日志只会发现"召回率低"，在现场才看得出"切块太粗" |
| 召回率 | Recall | 该找到的资料有没有被找到 | 它比"回答准确率"更早暴露问题 |
| 重排 | Rerank | 对候选结果再排一次序 | 便宜的提效手段，常在被问到时才想起 |
| ★ 评测集 | Eval Set / Golden Set | 一组人工标注、可复用的测试题目 | 能签字的从来不是"感觉挺准"，是它 |
| 评测框架 | Eval Harness | 自动跑评测、出分、比对历史的工具 | 有了它才谈得上回归；没有它每次改动都是赌 |
| 回归测试 | Regression Test | 新改动没把老能力弄坏 | AI 系统最常见的退化方式是静默的 |
| 智能体 | Agent | 会自己决定调用哪些工具、多步完成任务的程序 | 甲方说"要个 Agent"时，八成想要的是工作流 |
| 工具调用 | Tool / Function Calling | 让模型以结构化方式调用你的函数 | 真正的难点在参数校验和错误契约 |
| 微调 | Fine-tuning | 用领域数据继续训练模型 | 报价高、周期长、效果常可用提示词与检索替代 |
| ★ 上下文工程 | Context Engineering | 决定模型一次看到什么、看多少 | 这是 2026 年 JD 里最时髦也最实的一栏 |

顺带一句：国内有 JD 把"精通上下文工程、RAG、MCP、SDD、Harness 工程"写在同一行里。名词可以堆，判断标准只有一条——**你能不能说清上一次它是怎么失败的。**

## 四、可靠性、成本与观测（8 个）

| 中文 | 英文 | 一句话解释 | 现场为什么绕不开 |
| --- | --- | --- | --- |
| ★ 尾延迟 | P99 / Tail Latency | 最慢那 1% 的请求要多久 | "平均 1.2 秒"会在现场被 P99 打脸：用户只记得那一次 12 秒 |
| 单次调用成本 | Cost per Request | 一次问答花掉多少钱 | 决定这个场景能不能天天用 |
| Token 预算 | Token / Context Budget | 一次调用允许模型看多少内容 | 超了会变慢变贵，砍了会变笨 |
| 降级策略 | Fallback / Degradation | 模型不可用或不达标时改走什么路径 | 没有降级方案的系统不算上生产 |
| 限流 | Rate Limiting | 每秒/每人允许多少次调用 | 客户 IT 一定会问，答不上就排队评审 |
| 可观测性 | Observability | 出事时能从日志与指标重建发生了什么 | 审计与安全团队判断你有没有资格上线 |
| 链路追踪 | Tracing | 一次请求穿过哪些服务、各花多久 | 也是把责任讲清楚的技术版本 |
| 坏例回收 | Failure Harvesting | 把失败样本收进评测集的流程 | 上线后口碑不掉链子靠这个 |

## 五、国内特有的一层（11 个）

这些词在美国的 JD 里几乎不出现，但在中文世界的现场，它们决定项目能不能收钱。

| 中文 | 大概对应 | 一句话解释 | 现场为什么绕不开 |
| --- | --- | --- | --- |
| ★ 信创 | ITSM / 国产化替代 | 用国产 CPU、OS、数据库、中间件构成的替代栈 | 适配不是可行性问题，是一份要交的报告 |
| 指令集适配 | X86 / ARM64 / LoongArch / MIPS | 同一套代码要在四套指令集上跑 | 依赖库、驱动、监控探针都要逐条核实 `[B]` |
| 国产数据库 | 达梦 / 人大金仓 / OceanBase / openGauss | 语法与工具链兼容度参差不齐 | "官方声称支持"和"实测通过"之间隔一个项目 |
| ★ 等级保护 | 等保 2.0 | 信息与系统的安全分级要求 | 通不过等保，前面所有工作都是沉没成本 |
| 国密算法 | SM2 / SM3 / SM4 | 密码体系要换成国产算法 | 涉及加密、签名、传输，常被漏在方案外 |
| 数据不出域 | 本地化部署 / 私有化 | 数据不得离开客户机房或指定边界 | 决定了你能不能用任何境外工具链 |
| 封网 | Change Freeze | 特定时期禁止一切变更（重要会议、节假日） | 你的上线窗口可能因此凭空消失两周 |
| 一体机 | Appliance | 软硬件打包交付的国产设备形态 | 报价与工期都被它绑架，但也常是唯一可行方案 |
| ★ 初验 / 终验 | Staged Acceptance | 分模块初验与整体终验两个关口 | 终验现场可能"新换了一位分管领导" `[C]` |
| 质保金 | Retention | 尾款中押住一年左右的金额 | 常见口径是 15%、押 18 个月（从业者转述，非国标）`[C]` |
| 日报台账 | Daily Log | 每天写进度、当日闭环的记录制度 | 在国内它是被信任的方式，不是形式主义 |

::: warning 别把国内这一层当"额外负担"
它其实是另一套约束下的工程题。工信部 2026 年那份通知里对这支队伍的能力画像只有十二个字：**懂业务、通模型、知安全、能交付** `[A]`。四项里两项（安全、交付）落在这一组词上。
:::

## 六个"听起来专业但会误导人"的说法

| 说法 | 问题在哪 | 换成什么 |
| --- | --- | --- |
| "准确率 95%" | 没说在哪个评测集上、由谁标注、正例怎么定义 | "在业务方共同标注的 320 条评测集上，指标 X 为 0.95" |
| "系统很稳定" | 形容词，无法验收 | "连续 30 天无 S1 事故，P99 ≤ 3 秒" |
| "支持多种数据源" | 数量与深度都不明 | "已实测打通 A/B/C 三套系统，字段映射清单见附件" |
| "响应很快" | 平均值会骗人 | "P95 1.4 秒，P99 4.2 秒，含检索与生成" |
| "我们做了 Agent" | 大多数需求其实是固定工作流 | "这是一个 4 步工作流，其中 1 步允许模型自行选择工具" |
| "FDE 就是全能工程师" | 把岗位说成了许愿池 | "对结果负责的工程师，工作地点暂时在客户那边" |
