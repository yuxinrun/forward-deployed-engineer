# 面试怎么考

先把最容易被写错的一句话说清楚：**没有任何一家公司公布过 FDE 岗位的官方通过率。** 下面所有轮次和百分比，来源是面试指南、从业者回忆和第三方面经归纳 `[B]`/`[C]`。四份材料给出四种流程（5 轮、5 关、7 轮、4–6 轮），它们互相矛盾，而"矛盾"本身就是这一行早期阶段的证据。

不过这四份材料在三件事上完全一致，而这三件事就是你唯一能准备的：

## 一致的那三件事

**第一件：给你一个说不清的问题。** Palantir 被访者的原话是 "Palantir really cared about how I approached vague problems. They did not spoon-feed requirements and expected structure."（他们关心你怎么接近模糊问题，不会把要求喂到你手上，只等你自己给出结构）`[B]`。

**第二件：看你能不能在现场跟人协作。** 第三方描述 Palantir onsite 形式时提到"现场协作"环节；但本站**未找到可逐字引用的官方"team day" JD**，所以这一条只能写成"多轮 + 现场协作环节"，不能写成官方流程 `[C]`。

**第三件：逼你为自己的判断辩护。** 一份求职回忆里，OpenAI 技术面被追问两句："why this chunking strategy"（你为什么用这种切块策略）和 "how do you know your AI system is actually working well?"（你怎么知道你的 AI 系统真的好用）`[C]`。这两句和编码轮那道"并捍卫你的切块选择"是同一件事：**答案不重要，你能不能把取舍讲清楚才重要。**

## 编码轮：考的是工程习惯，不是智商

指南原话："这在大多数招聘 FDE 的公司是刻意非 LeetCode 式的算法题，它模拟真实部署工作。" `[C]` 示例题五道，本站全抄在上面的图里，共同特征很明显：

- 输入是脏的（不一致引号、缺失字段）
- 约束是外部给的（每用户 + 全局限额、不稳定第三方 API）
- 交付物是"能跑 + 有边界"（重试上限、加速方案）
- 至少一题要求你**说明取舍**

失分总结也是同一来源给的："干净、可读、有测试的代码优先于聪明的最优解。" `[C]` 这句话在面试里的实操含义是：**先问环境和数据量，再写代码；写完先讲错误处理，再讲优化。** 不澄清约束就开始写，是指南点名的第一挂点。

## 模糊案例轮：真正的签名轮

两份材料给出的真题，放在一起看特别有用，因为它们都不是技术问题：

> 管理层想要让 Agent 直接修改已有的生产系统，但安全团队表示坚决反对，工程师应该听谁的？ `[C]`

> 一家公司已经购买了 AI 服务……反馈说根本不好用，问题是出在 AI 模型、数据、权限，还是选错了工作流？ `[C]`

第二题的正确处理顺序，恰好是本站在生命周期那一章写的顺序：**先看数据和权限，再看工作流，最后才怀疑模型**。而客户在真实现场给的从来不是表结构，是麻烦——Palantir 一侧流传的客户提问是三句："为什么我们的航班总在延误？""怎样更有效发现洗钱？""我们为什么在流失客户？" `[B]`

指南给的挂点也很直白：**急着给方案，不先拆假设。** 一句可复用的开场是"我先把不知道的东西列出来，再给一个我会错的版本"——它同时解决模糊和压力两件事。

## 客户模拟轮：面试官扮客户

流程里最不像面试的一轮，通常 45 分钟，你要当场问出需求。一份转述说这一轮"淘汰约六成" `[C]`——**这个数字只能当印象用，不是任何公司的官方口径。**

三个被点名的挂点：被质疑一次就改口（没有立场）；全程只讲技术名词（客户听不懂）；以及最狠的一个——**问完需求就开始介绍产品**。这一轮的过法是反的：多问，少说，把对方的原话记下来并复述一遍。

从业者给的另一道"人肉验伪题"更适合当准备材料："你遇到过最难的客户场景是什么？"——"真干过的人会讲具体细节，比如'客户数据格式乱七八糟，光清洗就花了一周'；没干过的人会讲得很空泛，比如'客户需求变更频繁，沟通比较困难'" `[C]`。

## 价值观那一关

Anthropic 的流程里被转述有"使命/价值观冲突"一关，会出现"股价归零"这类问题 `[C]`；OpenAI 的三轮虚拟 onsite 里则包含 Hiring Manager、Solution Design、Technical Deep Dive `[C]`。这一关没法准备答案，但可以准备**一个真实的失败**：你判断错了、代价是什么、你怎么发现、你之后改了哪个习惯。四个环节齐了，这一关基本能过；缺任何一个，就会听起来像话术。

## 反过来，你要问的七问

这份清单来自一位从业者的自述——他说自己面试时会当面问这七句 `[C]`：

| 你问什么 | 你在测什么 |
| --- | --- |
| 交付的是这家客户的一套系统，还是产品的一个功能？ | 你是交付人力，还是产品的前哨 |
| 考核看使用率和稳定性，还是看验收单？ | 谁定义"成功" |
| 现场的反馈回到哪儿，回去以后谁接？ | 有没有产品回流机制 |
| 薪资挂在哪一档？ | 序列（工程 vs 专业服务） |
| 驻场是手段，还是全部工作？ | 你会不会变成纯外包 |
| 要不要背增购？ | 你是不是销售的延伸 |
| 上线以后，效果谁负责？ | 责任边界是否清楚 |

他的结论一句话就够："对面要是支支吾吾，说'这个看项目情况'，基本就有数了。" `[C]`

## 国内这一侧：面试信息更薄，但正文能反推

本站**没有取到国内 FDE 岗位的一手面试记录**（招聘平台正文需登录，公开面经极少）。能做的反推是从职责正文读考点：写了"驻场占比 50% 以上"的，一定会问你能不能长期出差 `[A]`；写了"日报""台账""当日闭环"的，会问你的响应速度和文档习惯 `[B]`；写了"信创适配""数据不出域"的，会问你有没有在无外网环境装过东西 `[C]`；写了"高提成""豆包企业版"的，那是渠道销售，问的是客户资源 `[B]`。

还有一句值得带进面试现场的自嘲（同样是从业者口径 `[C]`）：**"一次招 20 个 FDE……师傅都不够分。"** 如果对面一次招 20 个，你要问的不是技术栈，是谁带我。

::: warning 本页所有轮次和通过率都是二手口径
5 轮、5 关、7 轮同时存在，通过率只有三轮有数字，且来自面试指南与回忆 `[C]`。**看到任何一篇写"FDE 面试官方流程如下"的文章，可以直接判断它没有官方来源。** 本站选择把四份互相矛盾的流程并排画出来，而不是替读者挑一个最顺眼的。

## 面试前 72 小时能做的三件事

<div class="mp-steps">
  <div class="mp-step">
    <b>01</b>
    <div>
      <strong>把一个项目讲到"取舍"这一层</strong>
      <p>练习方式：对着录音讲 6 分钟，必须包含<b>三个数字、一次失败、一个不是技术决定的决定</b>。"我们把切块从按字数改成按段落切，chunk size 降了约 300 字，代价是索引时间变长，我先做的是评测集"这种句子，比任何自我介绍都有说服力 <code>[C]</code>。</p>
    </div>
  </div>
  <div class="mp-step">
    <b>02</b>
    <div>
      <strong>手写一遍"脏数据三件套"</strong>
      <p>限流器、带抖动的指数退避、乱七八糟 CSV 的解析——三题各写一次，写完自己 review 错误处理。这三题覆盖了编码轮的全部原型，而且都不需要刷题 <code>[C]</code>。</p>
    </div>
  </div>
  <div class="mp-step">
    <b>03</b>
    <div>
      <strong>准备一次"我不知道"</strong>
      <p>模糊案例轮的得分点恰恰是<b>承认不知道并把它拆成可验证的小问题</b>。准备一句固定开场："这里有三个可能，我先说我会怎么分别验证。"——这是被访者原话里唯一可以直接抄的结构 <code>[B]</code>。</p>
    </div>
  </div>
</div>
