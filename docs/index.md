<div class="mp-eyebrow coral">Requirements · 招聘方到底在写什么</div>

## 16 份能读正文的 JD 里，出现频率最高的不是算法

<p class="mp-lead">把 JD 的每句话按"出现了几个岗位"数一遍，结论会颠覆很多准备方向：写得最狠的是"能在模糊里推进"和"把客户系统接进来"，而不是"精通机器学习"。</p>

| JD 里写的事 | 出现密度 | 这决定了你面试要不要准备 |
| --- | --- | --- |
| 端到端负责（设计、搭建、部署、运维一起背） | 几乎每份都有 | 必考：讲一个你从 0 到有人用的项目 |
| 在模糊、信息不全的需求里推进 | 高频，措辞最一致 | 必考：给你一个说不清的问题，看你先问什么 |
| 与客户、非工程角色直接协作 | 高频 | 必考：客户模拟轮，面试官扮演不买账的人 |
| Python 或 TypeScript 之一 | 高频 | 编码轮刻意不是算法题：脏数据、限流、重试 |
| API 集成 / 数据管道 / SQL | 高频 | 会考，且考得很具体 |
| 身份、权限、安全与合规 | 中高频，越靠近甲方越硬 | 方案设计里没写权限边界会当场扣分 |
| 评测（evals）与质量度量 | 中频，正在快速上升 | 新增重点：你怎么证明它"够好可以上" |
| 云与容器、部署与回滚 | 中频 | 常规，但必须有回滚 |
| 大模型 / RAG / Agent 具体技术 | 中频 | 会问，但更问取舍而不是名词 |
| 出差与驻场比例 | 7 份明确写了数字 | 一定要反问：写在合同的哪一句 |
| 明确写"需要机器学习研究经验" | 极少 | 所以别先去刷论文 |

<p class="mp-lead" style="margin-top:14px">完整拆解与逐句原文在<a href="./job/jd.html">JD 拆解</a>；把"必须会 / 加分 / 不用碰"分成三档的地图在<a href="./job/hard-skills.html">硬技能地图</a>。</p>

<div class="mp-eyebrow coral">Failure modes · 先学会它怎么死</div>

## 十条常见翻车点里，只有三条的根因是技术

<p class="mp-lead">这一节是整本站里性价比最高的部分：知道坑在哪，比多学一个框架值钱得多。Rand 基于 65 次访谈的结论也指同一件事——AI 项目失败的五条根因里，没有一条是"模型不够强"。</p>

<div class="mp-grid">
  <div class="mp-card tone-coral"><span class="mp-num">01</span><h3>拿干净样本做 POC</h3><p>试点用的是人工挑过的 200 条数据，生产上是十二年的空值、错格式和两个系统各写一半。POC 越漂亮，生产化越难看。</p><span class="mp-go">见「试点到生产」</span></div>
  <div class="mp-card tone-coral"><span class="mp-num">02</span><h3>顺手加个小功能</h3><p>甲方最常的一句话是"再加个按钮就行"。每句都行，加起来就是没人验收的项目。范围蔓延从来不是被批准进来的，是被顺手放进来的。</p><span class="mp-go">见「范围与责任」</span></div>
  <div class="mp-card tone-coral"><span class="mp-num">03</span><h3>没有评测，没人签字</h3><p>"准确率不错"这句话没法被验收，也没人敢为它签字。能签字的是：多少条样本、什么指标、谁认可这个阈值。</p><span class="mp-go">见「评测与签字」</span></div>
  <div class="mp-card tone-coral"><span class="mp-num">04</span><h3>安全评审最后两周才上桌</h3><p>架构早定好了，评审来了一句"数据不能出域"。在国企和金融机构里，这不是一个问题，是一个句号。</p><span class="mp-go">见「合规与私有化」</span></div>
  <div class="mp-card tone-coral"><span class="mp-num">05</span><h3>平均延迟被 P99 打脸</h3><p>演示的时候说"平均 1.2 秒"。真实用户碰到的是那 5% 的 12 秒，而且他只会记得这一次。成本和延迟都要按尾部算。</p><span class="mp-go">见「从 Demo 到生产」</span></div>
  <div class="mp-card tone-coral"><span class="mp-num">06</span><h3>老板报喜，员工不用</h3><p>最危险的数字不是准确率高，是没人用还对外说成功。第三周口碑开始漏气的时候，通常已经来不及补。</p><span class="mp-go">见「采用度」</span></div>
</div>

<div class="mp-eyebrow">Evidence · 三级可信度标注</div>

## 你在别处看到的数字，这里都写了它能不能用

<p class="mp-lead">本站全文用三个等级标注每一条事实。它们不是"信不信"，是"你能拿去用到什么场合"。</p>

| 等级 | 含义 | 能用来做什么 |
| --- | --- | --- |
| `[A]` | 本站读到了原始页面或原始文件，句子能逐字核对 | 可以直接引用，最好把出处一起给出去 |
| `[B]` | 一手信息的可靠转述，或原文有但口径受限（如媒体报道的薪资数字） | 可以引用，但必须带上限定句：是预测/是广告价/是某一家的说法 |
| `[C]` | 从业者自述、自媒体整理、培训机构宣传 | 只用来讲"有人这么感受过"，不要写进任何正式材料 |

<p class="mp-lead" style="margin-top:14px">三条本站自己踩过的坑，写在明处：国内招聘平台的岗位正文大多需要登录或反爬，能直读正文的样本很少；所有面试轮次与通过率都是二手口径，没有一家公司公布过官方通过率；Gartner、S&amp;P、RAND 三组"AI 项目失败率"口径互不兼容，绝不能叠在一起说。</p>
